# 교육 제안서 만들기

고객사에 그대로 보낼 수 있는 수준의 교육 제안서를 만든다. 항상 내용 초안 Markdown과 16:9 HTML 슬라이드 덱을 함께 만든다.

## 브랜드 고정값

아래 값은 `workspace/memory/facts.md`에서 확인한 위드드림컨설팅의 확정 정보다. 회사 표기와 덱 디자인에 그대로 사용한다.

- 회사 이름: 위드드림컨설팅
- 로고 글자: GD
- 진한 색: `#4D064B`
- 기본 색: `#9B0D97`
- 강조색: `#F5A623`
- 옅은 색: `#F7EBF7`

## Step 0 — 착수 전 확인

제안서를 쓰기 전에 아래 6가지를 한 번에 모아서 묻는다.

1. 고객사 이름과 업종
2. 교육 대상: 직급·직무·인원
3. 교육 시간
4. 예산 또는 시간당 단가
5. 일자 확정 여부
6. 이 교육을 왜 하려는지: 담당자가 풀려는 문제

1·2·3·6 중 하나라도 비어 있으면 제안서를 쓰지 않는다. 빠진 필수 항목을 먼저 묻는다. 특히 6번이 없으면 어느 회사에나 붙는 표준 커리큘럼이 되므로 반드시 확인한다.

필수 답변을 받으면 추가 질문 없이 끝까지 작성한다. 예산·날짜·인원처럼 받지 못한 값은 추정하지 않고 `확인 필요`로 둔다.

## 산출물

경로는 스타터킷 루트를 기준으로 한다. 스킬 폴더 안에 `workspace`를 만들지 않는다.

1. 내용 초안: `workspace/결과물/<날짜>_<고객사>_제안서초안.md`
2. 고객 발송용 슬라이드 덱: `workspace/결과물/<날짜>_<고객사>_제안서덱.html`

날짜가 정해지지 않았다면 파일명 날짜 자리에 `확인필요`를 쓴다. 고객사 이름이 없으면 Step 0에서 확인한 뒤 제작한다.

## 작성 원칙

- 모듈은 4개 안팎으로 구성한다
- 각 모듈에는 `모듈명 / 학습 목표 / 주요 내용 / 학습자 활동(+몇 분)` 네 줄을 모두 쓴다
- 모듈을 제목과 한 줄 설명으로 끝내지 않는다
- 각 활동 시간을 더해 요청한 총 교육 시간과 일치하는지 검산한다
- 문서에 `시간 합계 검산: 총 ○분으로 요청 시간과 일치함`을 적는다
- 기대효과는 담당자가 윗선에 보고할 수 있는 관찰 가능한 문장으로 쓴다
- `역량이 향상됩니다`처럼 측정할 수 없는 표현을 쓰지 않는다
- `교육 후 2주 내 각 팀이 적용 사례 1건씩을 제출합니다`처럼 시점·주체·행동·결과를 드러낸다
- 견적 표에는 `단가 × 시간` 계산 과정을 보인다
- 견적에 공급가, 부가세, 합계를 구분하고 부가세 별도 여부를 반드시 적는다
- 사용자가 단가를 주지 않으면 계산 칸과 금액을 `확인 필요`로 둔다

## 사실 보호

- 듣지 않은 금액·날짜·인원·실적을 지어내지 않는다
- 모르는 값은 `확인 필요`로 둔다
- 실제로 하지 않은 교육을 실적으로 쓰지 않는다
- 사용자가 준 자료를 줄일 때 수치와 고유명사는 하나도 빼지 않는다
- 줄이는 것은 문장 길이이며 데이터가 아니다

## 문장 규칙

이 규칙은 초안과 덱에 들어가는 모든 글에 적용한다.

- 제목은 `[핵심 수단] + [정량 수치]`로 쓴다
- `업무 효율성 향상 방안` 같은 추상적 제목을 쓰지 않는다
- `처리 시간을 40% 줄이는 보고 절차 재설계`처럼 수단과 수치를 드러낸다
- 한 문장에는 메시지 하나만 담고 두 문장을 넘기지 않는다
- `~하며, ~하고, ~함으로써`로 길게 잇지 않고 문장을 끊는다
- 서술형 문장에는 마침표를 찍는다
- `-`로 시작하는 개조식 항목에는 마침표를 찍지 않는다
- 개조식은 명사만 나열하지 않는다
- 개조식 한 줄에 `[주체] + [구체적 행동] + [결과]`를 담는다
- 예: `- 담당자 사전 협의 1회로 업종 사례를 맞춰 당일 이해도 편차 축소`

## 쓰지 않을 단어

아래 단어와 근거 없는 형용사·부사를 쓰지 않는다. 사실과 숫자로 바꿔 쓴다.

`대폭 · 획기적인 · 혁신적인 · 엄청난 · 극대화 · 다양한 · 효율적인 · 최적의`

## 표 작성 규칙

- 세로 격자선을 넣지 않고 가로 구분선만 넣는다
- 굵게와 강조색은 실제 수치와 변화량에만 쓴다
- 표의 주인공은 수치와 변화량이다
- 표 머리는 진한 색 배경에 흰 글씨로 만든다

## HTML 덱 규격

- 슬라이드 한 장은 `1440px × 810px` 고정 16:9 판형으로 만든다
- 한 장에 내용이 넘치면 글씨를 줄이지 않고 장을 나눈다
- 서체는 인터넷 연결 없이 동작하는 `Noto Sans KR` 계열과 로컬 폴백만 쓴다
- 인터넷에서 폰트나 이미지를 불러오지 않는다
- 자바스크립트를 쓰지 않는다
- 인쇄 시 그대로 PDF가 되도록 `@page{size:1440px 810px;margin:0}`를 넣는다

## 면적 채우기

빈 장을 만들지 않는다. 글자 크기나 큰 여백으로 빈 공간을 숨기지 않고 아래 구조로 면적을 채운다.

- 모든 본문 장에는 문단·표·카드 묶음·목록·강조 박스 중 블록을 3개 이상 넣는다
- 모든 본문 장의 표 또는 카드 묶음 하나에는 반드시 `class="grow"`를 붙인다
- 표는 4행 이상으로 만든다
- 카드 묶음은 카드 3개로 만든다
- 목록은 4항목 이상으로 만든다
- `margin-bottom:200px` 같은 큰 여백으로 빈 곳을 채우지 않는다
- 제목과 한 줄만 있는 장을 만들지 않는다

본문 장은 제목을 제외하고 장당 250자 이상을 목표로 한다. 250자를 채우지 못하면 내용을 지어내지 않는다. 해당 장을 없애 앞 장에 합친다. 사실에 근거해 보충할 수 있으면 먼저 보충한 뒤 다시 센다.

정보가 모자라 `확인 필요`가 많은 장은 250자 미만이어도 된다. 이때는 무엇을 받으면 채울 수 있는지 한 줄로 적고 마지막 점검표에 사유를 쓴다. 장 수가 적어도 되며 적은 장을 꽉 채운다.

## 장 구성

아래 순서를 기본으로 한다. 정보 부족으로 장을 합칠 때도 내용 순서는 유지한다.

1. **표지** — 진한 색 그라데이션, 로고 글자 `GD`, 영문 라벨, 큰 제목, 강조색 부제, 하단 `고객사 | 대상 | 시간`
2. **목차** — 01~06 번호와 한 줄 설명
3. **필요성** — 고객이 말한 문제를 그대로 인용해서 시작
4. **기대효과** — 당일·2주·1개월 시점별 표와 확인 방법
5. **설계 방향** — 4단계 카드와 학습자 활동 비중
6. **커리큘럼** — 시간·구분·세부내용·방법·소요 표, 합계 행, 하단 카드 3개
7. **주요 내용 1** — 첫 번째 핵심 모듈
8. **주요 내용 2** — 두 번째 핵심 모듈
9. **견적서** — 요약 카드 4개, 산출 내역 칸이 있는 상세 표, 공급가·부가세·합계, 주석
10. **강사 소개** — 경력·학력·자격 3칸과 강의 영역 표
11. **요약·다음 단계** — 요약 카드 4개, 진행 순서 표, `확인 부탁드리는 것` 박스
12. **THANK YOU** — 표지와 같은 컬러 배경

## 모든 본문 장의 공통 요소

- 좌상단 번호 배지와 영문 섹션명: 예 `01 / WHY THIS TRAINING`
- 명사가 아닌 문장형 제목
- 우상단 로고 글자 `GD`
- 우하단 쪽번호
- 진한 색 배경과 흰 글씨의 표 머리
- 헤더 아래의 메인 색 구분선
- 메인 색 번호 배지

제목은 `기대효과`처럼 쓰지 않는다. `교육 후에 이런 것이 눈에 보입니다`처럼 문장으로 쓴다. 모든 제목에 핵심 수단과 확인 가능한 정량 수치를 함께 넣는다. 정량 수치를 받지 못했다면 지어내지 않고 `확인 필요`로 표시한다.

## 제작 후 자체 점검

두 파일을 모두 저장한 뒤 아래 항목을 실제 파일에서 확인한다.

1. 모든 본문 장에 `.hd` 헤더가 있는지 확인한다
2. 모든 본문 장의 헤더 아래 선과 번호 배지가 `--main`을 쓰는지 확인한다
3. 첫 장 `.cover`와 마지막 장 `.end`가 컬러 배경인지 확인한다
4. 모든 본문 장에 블록이 3개 이상인지 확인한다
5. 모든 본문 장에 `class="grow"`가 하나 이상인지 확인한다
6. 각 본문 장의 제목을 제외한 표시 글자 수를 센다
7. 250자 미만인 장은 앞 장에 합치거나 사실에 근거해 보충하고 다시 센다
8. 필수 정보 부족 때문에 250자 미만인 장만 예외로 두고, 필요한 자료를 그 장과 보고에 적는다
9. 시간 합계가 요청 시간과 일치하는지 확인한다
10. 견적의 단가×시간, 공급가, 부가세, 합계 계산이 맞는지 확인한다
11. HTML에 외부 인터넷 주소와 자바스크립트가 없는지 확인한다

## 마지막 보고

먼저 아래 표를 보여준다. 표지와 마지막 장은 헤더가 없으므로 헤더 색에 `해당 없음`을 적는다. 본문 장의 헤더 색에는 `#9B0D97`을 적는다.

| 장 | 제목 | 글자수 | 헤더 색 | 판정 |
|---:|---|---:|---|---|
| 1 | 실제 제목 | 실제 글자수 | 해당 없음 | 통과 |
| 2 | 실제 제목 | 실제 글자수 | #9B0D97 | 통과 |

250자 미만인 본문 장이 있으면 보고부터 하지 않는다. 앞 장에 합치거나 사실에 근거해 보충한 뒤 다시 세고 최종 수치만 보고한다. `확인 필요` 정보 때문에 예외가 된 장은 판정에 `확인 필요 — 필요한 자료`를 적는다.

표 아래에는 다음 세 가지만 간결하게 적는다.

- 내용 초안의 전체 경로
- 슬라이드 덱의 전체 경로
- 문서 전체의 `확인 필요` 항목 목록

마지막 줄에는 반드시 다음 문장을 적는다.

`덱은 브라우저로 열고 Ctrl+P → 대상을 PDF로 저장하면 됩니다`
