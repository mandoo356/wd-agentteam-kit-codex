# flow-image-JJ — Google Flow 이미지 배치 생성

Playwright로 Chrome 창을 띄워 Google Flow를 구동하고, 이미지를 여러 장 생성해 원본 해상도로 내려받는다.
Flow에는 공개 API가 없으므로 전용 크롬 프로필에 로그인 세션을 1회 저장해두고 재사용한다.

⛔ **헤드리스로 실행하지 말 것.** Google이 헤드리스 브라우저의 생성 요청을 403으로 차단한다
(다른 API는 200이라 "일일 캡 소진"으로 오진하기 쉽다). 스크립트는 창 띄우기가 기본이고,
`--headless` 는 DOM 정찰 용도로만 쓴다. 자세한 증상·판별법은 references/flow-internals.md 참조.

## 🔴 사전 조건 (반드시 먼저 확인)

이 스킬이 동작하려면 사용자 PC에 다음이 **모두** 준비되어 있어야 한다.
하나라도 없으면 작업을 시작하기 전에 사용자에게 안내하고 설치/준비부터 진행한다.

| # | 필요 항목 | 확인 방법 | 없을 때 |
|---|---|---|---|
| 1 | **Python 3.10+** | `python --version` | python.org에서 설치 (Windows는 "Add to PATH" 체크) |
| 2 | **playwright 패키지** | `python -c "import playwright"` | `pip install playwright` |
| 3 | **시스템 Chrome** | Chrome 브라우저가 설치되어 있는가 | google.com/chrome 에서 설치 (`channel="chrome"` 을 쓰므로 별도 브라우저 다운로드 불필요) |
| 4 | **Google Flow를 쓸 수 있는 Google 계정** | https://labs.google/fx/tools/flow 접속 → 로그인 → 이미지 생성이 되는가 | Google AI(Gemini) 구독 계정 필요. Flow 접근이 안 되는 계정이면 이 스킬을 쓸 수 없다 |
| 5 | **본인 Google 계정 1개 이상 로그인 등록** (아래 최초 설정) | `python scripts/flow_probe.py` 가 SESSION에 이메일을 출력하는가 | `python scripts/flow_login.py` 실행 후 창에서 직접 로그인 |

## 최초 설정 — 본인 Google 계정 등록 (필수, 1개 이상)

이 스킬은 **사용자 본인의 Google 계정**으로 동작한다. 설치 후 반드시 계정을 1개 이상 등록해야 한다.

```bash
python ~/.claude/skills/flow-image-JJ/scripts/flow_login.py
```

크롬 창이 뜨면 **사용자가 직접** 본인 Google 계정으로 로그인한다
(에이전트는 자격증명을 절대 대신 입력하지 않는다 — 창을 띄운 뒤 사용자에게 로그인을 요청할 것).
세션은 `~/.claude/.image-flow-profile` 에 저장되며 **약 8시간** 유효하다.
만료되면 같은 명령을 다시 실행한다.

세션 유효 여부만 빠르게 확인하려면:

```bash
python ~/.claude/skills/flow-image-JJ/scripts/flow_probe.py
```

### (선택) 계정을 여러 개 등록해 병렬로 쓰기

계정이 여러 개라면 `IMAGE_FLOW_PROFILE` 환경변수로 계정별 프로필을 분리해
여러 배치를 **동시에** 돌릴 수 있다.

```bash
# 두 번째 계정 등록 (창이 뜨면 그 계정으로 로그인)
IMAGE_FLOW_PROFILE="$HOME/.claude/.image-flow-profile-2" python .../scripts/flow_login.py

# 두 번째 계정으로 생성
IMAGE_FLOW_PROFILE="$HOME/.claude/.image-flow-profile-2" python .../scripts/flow_generate.py --prompts b.txt --out ./out-b
```

🔴 **같은 프로필로 두 작업을 동시에 돌리지 말 것.** 크롬은 하나의 user-data-dir을
두 프로세스가 붙잡으면 기동에 실패하고 프로필이 깨질 수 있다.
- 병렬 실행 시 반드시 프로필과 **저장 폴더(`--out`)를 모두 분리**한다 (같은 폴더면 파일명이 겹쳐 덮어써진다)
- 프로필이 깨졌으면: 프로필 폴더 삭제 후 `flow_login.py` 재실행
- 한 계정으로 순차 실행할 거면 앞 작업이 «완료» 로그를 찍은 뒤에 다음을 시작한다

## 기본 워크플로우

### 0단계 — 생성 전 반드시: 스타일 페이지를 열고 → 두 가지를 묻는다

이미지 생성 요청을 받으면 **바로 만들지 말고**, 아래 순서를 지킨다.

**(A) 먼저 스타일 대시보드를 새 창으로 연다 — 질문보다 먼저다.**

```bash
python ~/.claude/skills/flow-image-JJ/scripts/show_styles.py
```

이 스크립트가 https://jj-aiedu.vercel.app/style/card-styles.html 을 기본 브라우저로 연다.
실행 결과 `[OK]` 를 확인할 것. 열기에 실패하면 사용자에게 URL을 직접 안내한다.
**창을 안 띄우고 번호만 물어보면 안 된다** — 샘플 이미지를 눈으로 보고 골라야 한다.
사용자가 이미 번호를 지정한 경우에도 창은 띄운다 (샘플을 보고 마음을 바꾸거나 조합을 고를 수 있다).

**(B) 그 다음 두 가지를 질문한다** (사용자가 요청문에서 이미 지정한 항목은 건너뛴다):

1. **스타일** — "20종 중 번호로 골라주세요 (조합 가능: 예 '1번', '1번+19번')"
   번호 → 실제 프롬프트 레시피 매핑은 [references/card-styles.md](references/card-styles.md) 참조.
2. **사이즈(비율)** — Flow 설정 패널에 있는 5종을 그대로 제시한다:

| 비율 | 용도 예시 |
|---|---|
| `16:9` | 블로그 썸네일, 웹 배너, 유튜브, 문서 가로 삽화 |
| `4:3` | 문서 삽입용 일반 가로 |
| `1:1` | 인스타 카드, 앱 아이콘, 정사각 에셋 |
| `3:4` | 세로 삽화, 인쇄 유인물 |
| `9:16` | 쇼츠/릴스, 모바일 세로 |

⚠️ 출력 픽셀 크기를 단정해서 안내하지 말 것 (모델·비율 조합에 따라 달라진다). 비율 이름만 제시한다.
선택한 비율은 프롬프트가 아니라 **Flow 설정 패널**에서 지정된다 — `--ratio` 값을 스크립트가 UI에 적용한다.

또한 **요청에 이미지 파일 경로가 함께 왔는지 확인한다.** 경로가 있으면 그 사진들을
`--ref` 로 첨부해 생성한다 (아래 «참고 이미지 첨부» 절). 대화에 첨부만 된 이미지는
파일로 쓸 수 없으므로, 필요하면 로컬 경로를 알려달라고 요청한다.

### 1단계 — 프롬프트 작성

선택한 스타일 레시피(card-styles.md) + 사용자가 원하는 장면을 합쳐 **영문 프롬프트**를 만든다.
빈 줄로 구분된 텍스트 파일로 저장한다 (`#` 로 시작하는 줄은 주석).

⛔ **프롬프트에 방향·비율 표현을 절대 넣지 말 것** — `vertical composition`, `portrait`,
`landscape`, `square format`, `16:9` 같은 표현이 있으면 에이전트가 설정 패널의 비율을 무시한다.
(실측: `--ratio 3:4` + `vertical composition` → 9:16으로 나옴. 문구를 빼면 3:4로 정상.)
스크립트가 이런 표현을 자동 제거하고 `[정리]` 로 알려주지만, 애초에 넣지 않는 것이 원칙이다.

### 2단계 — 배치 실행

스크립트가 각 프롬프트에 `Generate an image:` 접두어를 자동으로 붙인다
(Flow는 에이전트 주도형이라 접두어가 없으면 생성은 돌지만 이미지가 0장 나오는 경우가 있다 — 실측).

```bash
python ~/.claude/skills/flow-image-JJ/scripts/flow_generate.py \
  --prompts prompts.txt \
  --model nano-banana-2 \
  --ratio 1:1 \
  --count 4 \
  --project "작업이름" \
  --out ./out
```

| 옵션 | 값 | 기본 |
|---|---|---|
| `--model` | `nano-banana-2-lite` / `nano-banana-2` / `nano-banana-pro` | `nano-banana-2` |
| `--ratio` | `16:9` `4:3` `1:1` `3:4` `9:16` | `1:1` |
| `--count` | 프롬프트당 1~4장 — **항상 기본값 4를 쓴다** | 4 |
| `--ref` | 참고 이미지 경로 (반복 지정·콤마 나열·폴더 가능) | 없음 |
| `--project` | 새 프로젝트에 붙일 이름 | 미지정 시 `image-flow YYYY-MM-DD HH:MM` |
| `--reuse` | 새로 만들지 않고 기존 프로젝트 재사용 | 꺼짐 |
| `--only` | 이 번호의 프롬프트만 (예: `2,5-7`) — 실패분 재시도용 | 전체 |
| `--timeout` | 프롬프트당 대기 초 | 420 |
| `--out` | 저장 폴더 | 미지정 시 **다운로드 폴더**`\image-flow\<프로젝트명>` |
| `--headless` | 창 없이 실행 — **생성이 403으로 차단되므로 쓰지 말 것** | 꺼짐(창 띄움) |

`--prompts` 는 파일 경로 대신 `"프롬프트A||프롬프트B"` 문자열도 받는다.

### 3단계 — 결과를 사용자에게 보여준다 (필수)

저장만 하고 끝내지 말 것. **생성된 이미지를 대화창에 띄운다** (SendUserFile 등 파일 전송 도구 사용).
저장 폴더도 탐색기로 열어준다: `explorer "<out_dir>"` (Windows 기준)

## 참고 이미지 첨부 — 사용자가 경로를 준 경우 (CRITICAL)

**사용자가 이미지 파일 경로(사람 사진, 제품 컷, 참고 시안 등)를 주면 반드시 `--ref` 로 붙인다.**
프롬프트에 말로만 묘사하지 말 것 — 얼굴·복장·디자인이 실제 사진을 따라간다.

```bash
python .../scripts/flow_generate.py \
  --prompts prompt.txt --ratio 3:4 --count 4 \
  --ref "C:\사진\person_a.jpg" --ref "C:\사진\person_b.jpg"
```

경로 지정 방식 3가지 — 편한 것을 쓴다.
- `--ref A.jpg --ref B.jpg` (반복)
- `--ref "A.jpg,B.jpg"` (콤마)
- `--ref "C:\사진폴더"` (폴더 전체 — jpg/jpeg/png/webp만 수집)

프롬프트 본문에도 `using the attached photos as the exact face references`
처럼 **참조하라는 지시를 함께 넣는다.** 첨부만 하고 프롬프트에 언급이 없으면 반영이 약해진다.

⚠️ 알아둘 것
- **화풍 변환 정도만큼 닮음이 희석된다.** 웹툰·일러스트로 가면 "닮은 느낌" 수준이고,
  실사 스타일일수록 얼굴 일치도가 높다.
- 애셋 3번째부터는 항목 클릭만으로 추가되고 '프롬프트에 추가' 버튼이 안 뜬다.
  버튼 클릭 실패 로그는 무시해도 되고, 첨부 여부는 로그의 `[참고] 프롬프트에 첨부됨: 약 N/M장` 으로 판정한다.

## 장수는 항상 x4 (중요)

Flow는 설정한 장수를 **동시에 생성**한다. 1장이든 4장이든 소요 시간이 사실상 같으므로
장수를 줄일 이유가 없다. `--count` 는 건드리지 말고 기본값 4를 쓴다.
4장 중에서 가장 좋은 것을 고르는 것이 항상 이득이다.

## 한 요청당 총 4장 — 프롬프트는 1개만 (CRITICAL)

⛔ **한 번의 요청에서 만드는 이미지는 총 4장이다.** `--count` 는 **프롬프트 1개당** 장수이므로,
프롬프트를 여러 개 넣으면 프롬프트 수 × 4장이 되어 과잉 생성된다.

따라서 **프롬프트 파일에는 장면을 하나만 쓴다.** `프롬프트 1개 × --count 4 = 총 4장`.
장면 변주가 여러 개 떠오르더라도 임의로 여러 개를 만들지 말고,
**어느 장면으로 갈지 사용자에게 먼저 확인한 뒤 그 장면 하나만 4장** 뽑는다.
사용자가 명시적으로 "여러 장면 다 뽑아줘"라고 요청한 경우에만 프롬프트를 늘린다.

## 프로젝트 정책 — 실행마다 새 프로젝트 (기본)

**이미지 생성 요청을 받으면 항상 Flow에 새 프로젝트를 만들고 거기서 생성한다.** 스크립트 기본 동작이다.
`--project "작업이름"` 처럼 의미 있는 이름을 주면 Flow 계정에서 나중에 찾기 쉽다.
`--reuse` 는 한 프로젝트에 이어서 쌓고 싶을 때만 쓴다.

결과물: 저장 폴더에 `01_<슬러그>_1.jpg` 형식으로 저장되고 `report.json` 이 함께 생성된다.
`--out` 을 주지 않으면 **사용자 PC의 다운로드 폴더** 아래 `image-flow\<프로젝트명>` 에 저장된다.

## 🔴 «몇 번이 빠졌는지»를 보고 빠진 것만 다시 뽑는다

`report.json` 은 **프롬프트 하나가 끝날 때마다 갱신**된다. 한도에 걸려 중간에 끊겨도
어디까지 나왔는지가 파일에 남는다. `results[]` 항목은
`{index, prompt, generated, saved[], error?}` 이고, `error` 로 실패 이유가 구분된다 —
`submit_failed`(제출 자체가 안 됨) · `flow_error`(Flow 오류 배너 = **한도 소진 의심**) ·
`timeout`(생성은 끝났는데 결과 0장).

**종료 코드** `0` 전부 성공 · **`3` 일부만 나옴** · `1` 한 장도 못 받음 · `2` 인자 오류.

`3` 이면 마지막 줄에 다시 돌릴 명령이 그대로 찍힌다. 번호와 파일명 접두사가 원본 순서라
**이미 나온 장은 덮이지 않는다.**

```bash
python .../scripts/flow_generate.py --prompts p.txt --only 2,5-6 --out ./out
```

한도 소진(`flow_error`)이면 같은 계정으로 재시도해도 소용없다 — 다른 계정 프로필로
전환해(`IMAGE_FLOW_PROFILE`) 빠진 번호만 다시 뽑거나, 다음 날 다시 시도한다.

## 모델 선택 기준

- `nano-banana-2-lite` — 무료 기본값이라 일일 캡이 가장 넉넉하다 (대량 시안용)
- `nano-banana-2` — 품질/속도 균형 (**기본 권장**)
- `nano-banana-pro` — 정밀한 디테일·복잡한 구성용. 일일 캡이 가장 빡빡하므로 최종본에만

## 한도와 비용

이미지 생성은 크레딧이 아니라 **모델별 일일 캡**으로 통제되는 것으로 보인다
(공식 크레딧 요금표에 이미지 모델이 없음). 대량 배치 전 소량으로 캡을 확인할 것.
캡에 걸리면 생성이 조용히 0장으로 끝나므로, `report.json` 의 `generated` 가 0 이고
`error` 가 `flow_error` 면 캡 소진을 의심한다.

## 문제 해결

| 증상 | 원인 / 대응 |
|---|---|
| `[ERROR] Flow 로그인 세션이 없습니다` | 세션 만료(약 8시간). `flow_login.py` 재실행 |
| 생성 0장인데 에러 없음 | 에이전트가 이미지로 해석하지 않았거나 일일 캡 소진. `--out` 폴더의 `FAIL_*.png` 로 화면 확인 |
| `제출 실패 (생성 시작 안 됨)` | 제출 버튼 클릭이 먹지 않음. 3회 재시도 후에도 실패하면 `FAIL_*.png` 확인 |
| `Application error: a client-side exception` | 프로젝트 URL로 직접 goto 한 경우. 반드시 홈에서 SPA 라우팅으로 진입 |
| 크롬 기동 실패 (`exitCode=21` 등) | 같은 프로필로 두 프로세스를 돌렸거나 프로필 손상. 프로필 폴더 삭제 후 `flow_login.py` 재실행 |
| 셀렉터를 못 찾음 (UI 개편) | `flow_probe.py` 로 DOM 재정찰 후 `references/flow-internals.md` 와 스크립트 갱신 |
| 다운로드 파일이 1KB 미만 | 세션 만료 상태로 받은 에러 페이지. 재로그인 |
| 결과 대신 **참고 사진이 그대로** 저장됨 | 기준선을 제출 전에 잡은 경우. 생성 시작 후 스냅샷하는지 확인 |
| `[참고] 프롬프트에 첨부됨: 약 0/N장` | 애셋 패널 셀렉터 변경. `FAIL_ref.png` 로 화면 확인 |

Flow의 DOM 구조·내부 API·언어 무관 셀렉터 전략 등 상세 내용은
[references/flow-internals.md](references/flow-internals.md) 참조. UI가 바뀌어 스크립트가 깨졌을 때 먼저 읽을 것.

## 스크립트 구성

| 파일 | 역할 |
|---|---|
| `scripts/flow_common.py` | 프로필/브라우저 기동, 세션 판정, 앱 진입 |
| `scripts/flow_login.py` | 1회 로그인 (창 띄움 — 사용자가 직접 로그인) |
| `scripts/flow_generate.py` | 배치 생성 + 다운로드 (메인) |
| `scripts/flow_download.py` | 프롬프트 파싱, 파일 저장 |
| `scripts/show_styles.py` | 스타일 20종 대시보드를 새 창으로 열기 (스타일 질문 전 필수) |
| `scripts/flow_probe.py` | DOM/네트워크 정찰 (UI 변경 대응) |
