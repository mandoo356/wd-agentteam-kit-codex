검은 창 매뉴얼

CMD와 PowerShell은 뭐가 다른가 · 파워셸이 없으면 어떻게 하나

한 줄 설치가 검은 CMD 창에서는 안 되는 이유와, 파란 PowerShell 창을 찾는 법 · 빌려 쓰는 법 · 아예 못 쓸 때 가는 길을 한 권에 모았습니다.

대상 수강생 전원 · 특히 회사 노트북 지참자 읽는 시간 8분 같이 볼 것 학습자교안 5쪽 「설치 확인 · 검은 창 여는 법」
1장 · 왜 CMD에서 안 됐나
설치 한 줄은 파워셸 말입니다. CMD는 그 단어를 모릅니다. 오류 문구로 30초 안에 판별합니다.
2장 · 두 창의 차이
생김새·프롬프트·되는 명령·안 되는 명령을 표 한 장으로. 이 과정에서 어느 명령이 어디서 되는지까지.
3~5장 · 파워셸이 없을 때
사실은 있습니다(찾는 법 6가지). 그래도 안 열리면 CMD에서 빌려 쓰는 한 줄. 회사가 완전히 막았으면 수동 설치.

1장 · 진단

왜 CMD 창에서는 설치가 안 됐나

이 과정의 설치 한 줄은 PowerShell 전용 명령으로 쓰여 있습니다. irm은 파워셸의 "인터넷에서 받아와라"(Invoke-RestMethod), iex는 "받은 걸 실행해라"(Invoke-Expression)의 줄임말입니다. CMD에는 이 두 단어가 없습니다. 그래서 CMD는 "그런 명령 모른다"고 답하고 멈춥니다.

배치 파일이 아닙니다.

창 색으로도 구별됩니다 — 다만 믿을 건 글자입니다

기본 설정에서 PowerShell은 짙은 파랑, CMD는 검정 바탕입니다. 그런데 윈도우 11의 「터미널」 앱은 둘 다 검정으로 보여 주기 때문에, 색보다 줄 맨 앞의 PS를 보는 게 확실합니다.

이 문서를 다 읽지 않아도 되는 경우

지금 창 맨 앞에 PS가 있으면 문제는 없습니다. 이 문서는 PS가 없는 창만 열리는 분, 또는 파워셸을 열었는데 빨간 글씨가 뜬 분을 위한 것입니다.

2장 · 비교

CMD와 PowerShell — 뭐가 다른가

둘 다 "글자로 컴퓨터에 지시하는 창"입니다. CMD는 1980년대 도스 시절부터 이어 온 옛 창, PowerShell은 2006년에 나온 새 창입니다. 새 창은 옛 창의 명령을 거의 다 알아듣지만, 옛 창은 새 창의 명령을 모릅니다. 설치 한 줄이 CMD에서 막히는 이유가 그것입니다.

3장 · 파워셸 열기

"파워셸이 없어요" — 사실은 있습니다

윈도우 10·11 노트북에는 Windows PowerShell 5.1이 반드시 들어 있습니다. 지울 수도 없습니다. "없다"고 느끼는 건 거의 전부 시작 메뉴에서 안 보여서입니다. 아래 여섯 가지 중 하나는 반드시 열립니다. 위에서부터 차례로 시도하세요.

  1. 시작 메뉴 검색. 윈도우키를 누르고 powershell 이라고 칩니다. Windows PowerShell(파란 아이콘)을 클릭. "PowerShell ISE"나 "(x86)"은 고르지 않습니다.
  2. 윈도우키 + X. 뜨는 메뉴에서 「터미널」 또는 「Windows PowerShell」을 클릭. 윈도우 11의 터미널은 기본이 파워셸입니다(맨 앞 PS 확인).
  3. 윈도우키 + R. 실행 창에 powershell 치고 Enter.
  4. 탐색기 주소창. 스타터킷 폴더를 연 상태에서 위쪽 주소창을 클릭하고 powershell 치고 Enter. 그 폴더에서 파워셸이 열립니다. cd가 필요 없습니다.
  5. CMD 안에서 부르기. 이미 검은 창이 열려 있으면 그 안에 powershell 이라고 치고 Enter. 같은 창 안에서 줄 맨 앞이 PS로 바뀝니다. 그 다음 설치 한 줄을 붙여넣으면 됩니다.
  6. 전체 경로로 직접 실행. 위 다섯이 다 안 되면 윈도우키 + R 에 아래 경로를 통째로 붙여넣고 Enter.
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
파워셸이 정말 있는지 CMD에서 1초 확인

검은 창에 아래 한 줄을 치면 파워셸 파일의 위치가 나옵니다. 경로가 한 줄 뜨면 있는 것입니다. "찾을 수 없다"가 뜨면 5장으로 가세요.

where powershell

정상이면 C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe 한 줄이 나옵니다.

「터미널」 · 「PowerShell 7」 · 「Windows PowerShell」 — 셋 중 아무거나

세 이름이 다 보여도 당황할 것 없습니다. 이 과정의 설치 한 줄은 셋 다에서 똑같이 됩니다. 줄 맨 앞에 PS만 있으면 됩니다.

4장 · 우회

CMD밖에 안 열릴 때 — 파워셸을 빌려 쓰는 한 줄

파워셸 창이 시작 메뉴에서 안 보이거나, 열어도 "이 시스템에서 스크립트를 실행할 수 없습니다"라는 빨간 글씨가 뜨는 회사 노트북이 있습니다. 그럴 때는 검은 CMD 창에서 파워셸을 잠깐 빌려 설치 한 줄을 대신 시킵니다. 아래 한 줄은 그 두 가지 상황을 한 번에 해결합니다.

CMD용 설치 한 줄

CMD 창(맨 앞에 PS가 없는 창)에 이 한 줄을 붙여넣고 Enter. 붙여넣기는 마우스 오른쪽 클릭입니다.

powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/mandoo356/wd-agentteam-kit-codex/main/install.ps1 | iex"
조각뜻
powershellCMD에게 "파워셸을 불러라". 파워셸은 윈도우 안에 항상 있으므로 이 호출은 됩니다
-NoProfile개인 설정 파일을 읽지 않고 깨끗하게 시작. 회사 PC의 이상한 설정에 걸리지 않게
-ExecutionPolicy Bypass"스크립트를 실행할 수 없습니다" 오류를 이번 한 번만 건너뜁니다. PC 설정은 바꾸지 않습니다
-Command "…"따옴표 안의 파워셸 명령을 실행. 안에 든 것이 바로 원래의 설치 한 줄
검증 — 강사 PC에서 확인함 (2026-09-05)

위 한 줄을 .cmd 파일에 그대로 적어 CMD에서 실행했을 때, Windows PowerShell 5.1이 깃허브에서 설치 스크립트 5,457자를 정상 수신했습니다. 그 뒤로는 파란 창에서 한 것과 똑같이 설치·환경점검이 이어집니다.

설치가 끝난 뒤에는

CMD로도 실습할 수 있습니다. 2장 표에서 본 것처럼 확인 4줄·py -3 점검.py·codex.cmd·npm ci·git status은 CMD에서 전부 똑같이 됩니다. 스타터킷 폴더에서 CMD를 여는 가장 쉬운 방법은 탐색기 주소창에 cmd 치고 Enter입니다(학습자교안 5쪽 여는 법 C). Codex를 시작하면 프로젝트와 /hooks의 새 훅을 신뢰하고 작업기록을 확인하세요.

Codex CLI는 두 창에서 같은 설치 명령을 씁니다

환경점검이 Codex CLI를 못 깔았을 때 손으로 깔아야 하면, CMD와 PowerShell 모두 아래 줄입니다. Node.js 설치 후 실행하세요.

npm.cmd install -g @openai/codex
이 한 줄도 빨간 글씨로 막히면

"이 앱은 시스템 관리자에 의해 차단되었습니다" 또는 "그룹 정책에 의해 차단"이라는 문구가 뜨면, 회사가 파워셸 프로그램 자체를 잠근 것입니다. 실행 정책 문제가 아니라서 Bypass로도 못 넘습니다. → 5장으로 가세요.

자동 설치가 만들어 주던 4개 폴더입니다. CMD에 아래 한 줄을 붙여넣으면 한 번에 만들어집니다. 그런 다음 수업 전에 제안서 3개 · 블로그 글 3개 · 로고 1개를 각 폴더에 넣습니다.

단계 5 — 파이썬 꾸러미 설치

탐색기 주소창에 cmd를 쳐서 스타터킷 폴더에서 검은 창을 열고 아래 한 줄. 슬랙 서버(모듈 4)에 필요한 꾸러미 5개가 깔립니다.

py -3 -m pip install -r slack-server\requirements.txt

단계 6 — 합격 판정

같은 창에서 아래 한 줄. ✅가 필수 항목에 전부 켜지면 자동 설치를 한 사람과 완전히 같은 상태입니다. ❌가 있으면 그 줄에 적힌 것만 고칩니다. 환경점검.bat이 열어 주던 브라우저 체크리스트는 이 PC에서는 뜨지 않습니다. 검은 창의 판정이 그 역할을 대신합니다.

py -3 점검.py 0
이 PC에서 달라지는 것 두 가지

① 수업 끝의 백업. 02_내작업_백업.bat도 파워셸을 부르므로 안 됩니다. 탐색기에서 스타터킷 안의 workspace 폴더 · .codex · .agents · AGENTS.md 폴더 · office\company.config.ts 파일 셋을 골라 오른쪽 클릭 → 「ZIP 파일로 압축」으로 직접 묶어 USB에 담습니다. .env와 node_modules는 넣지 않습니다.
② 슬랙 열쇠(.env) 편집. 메모장으로 합니다. 파워셸이 필요한 단계가 아닙니다.

PowerShell 7을 새로 깔면 되지 않나요

회사가 Windows PowerShell 5.1만 이름으로 막았다면 PowerShell 7(pwsh)은 열릴 수 있습니다. 그러나 같은 정책이 7도 막는 경우가 많고, 설치 자체가 관리자 승인을 요구하는 PC도 많아서 이 문서는 그 길을 기본으로 권하지 않습니다. 시도해 보고 싶으면 github.com/PowerShell/PowerShell/releases의 win-x64.msi를 받아 설치한 뒤 시작 메뉴에서 「PowerShell 7」을 열어 설치 한 줄을 붙여넣습니다. 열리면 3장, 안 열리면 위 여섯 단계입니다.

6장 · 범위 밖

맥북 · 크롬북 · 태블릿은 어떻게 하나

솔직하게 적습니다. 이 과정의 설치·점검·백업 도구는 전부 윈도우용입니다. .bat·.ps1·C:\Agent 경로·winget이 모두 윈도우 전제입니다. 맥에도 PowerShell 7을 깔 수는 있지만 설치 스크립트가 C 드라이브를 찾기 때문에 그대로는 돌지 않습니다.

기기이 과정안내

8장 · 강사용

수업 시작 5분 — 검은 창 진단 순서

설치 한 줄에서 막힌 수강생을 자리마다 찾아다니지 않도록, 시작할 때 전원에게 아래 순서를 한 번에 시킵니다.

  1. "윈도우키 누르고 powershell 치고 Enter." 파란 창이 열리고 맨 앞에 PS가 보이는 사람은 손 내립니다. 대다수가 여기서 끝납니다.
  2. 손 든 사람에게: "탐색기 주소창에 cmd 치고 Enter." 검은 창이 열리면 4장의 CMD용 한 줄을 화면에 띄워 붙여넣게 합니다. 실행 정책 오류였던 사람도 여기서 끝납니다.
  3. 그래도 "관리자에 의해 차단"이 뜬 사람은 보조 강사가 붙어 5장 여섯 단계로 갑니다. 다른 수강생이 환경점검을 돌리는 시간(약 10분)과 겹치므로 진도 손실이 적습니다.
  4. 맥북 지참자는 6장. 예비 노트북을 내주거나 관찰 참여로 안내합니다.

화면에 띄워 둘 두 줄

파란 창(PS)이면 위, 검은 창이면 아래

파워셸 — 맨 앞에 PS 가 보일 때
irm https://raw.githubusercontent.com/mandoo356/wd-agentteam-kit-codex/main/install.ps1 | iex

powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/mandoo356/wd-agentteam-kit-codex/main/install.ps1 | iex"
